# Spatial location conversion inventory

Source audit begun at `31a3a27` for the explicit deck-zero/schema47 packet. This is a bounded semantic sample of the named systems: search hits were followed into constructors, consumers and validators. ## Boundary for the next conversion

The shared reservation queries and depot capacity distinguish deck positions. Schema48 persists named pickup/delivery targets and material-source z, and converts their producers, physical lookups, cancellation and spoilage together. Observation/recording schema2 exposes the changed fields. Additional playable decks remain disabled; ground-only controller identities, pasture/birth and environmental topology, commands and multi-deck observation IDs remain dependencies. Schema49 converts crew care/need/home/personal-pickup targets; schema50 extends animal posts and physical carcass locations, with observation4. Schema51 converts persisted airlock locations and route endpoints, with observation5. Schema52 adds explicit room decks and horizontal gas/heat isolation, with observation6.

Convert named field schemas together with their producers, lookup/equality, save validation, routing and observation IDs. Preserve ID references and inventory ownership instead of recursively treating arbitrary arrays or `target` fields as positions. Keep extra decks disabled until horizontal systems distinguish z and explicit vertical links have their own rules.

This sample does not certify core save handling, every construction/industry consumer, command arguments, navigation, fire/reactors/suit supply, rendering, panels, telemetry or all movement assignments. Those require their own bounded review; this document is an inventory of confirmed dependencies, not a completion gate.

### Declared stairwell connection core

A shared stairwell record links two declared landings. Crew routes and physical steps honor hatch/condition state, preserve carried patients and cargo, and expose typed traversal records. Open hatches add finite gas/smoke/heat links and capped downward water flow. Paid construction, canonical multi-floor saves and floor UI now work; animal traversal and upstairs pasture work now operate through the shared jobs and saves. The vertical.hatch action uses a connection ID and shared player binding. Schema55 now admits validated links and up to8 declared contiguous levels. Paid stair jobs create the first upper landing; supported floor jobs extend it. Legacy pair routes never discard a cross-floor step. Production readiness checks stair routes only for qualified workers or stocked stores on other floors; it does not search from empty tiles.

Paid construction/save admission is implemented. The landing-deck renderer now filters upper tiles, actors, work, reserved parcels and impact markers; the compact floor selector now supports selecting and inspecting installed floors. Schema58 admits animal and carcass ownership on declared floors. Schema59 adds solar column occlusion and validates old power accounting before recalculating derived generation. Schema60 admits bound upper-floor airlock equipment, same-floor owned circuits and declared traveler destinations. Approaches follow actual stairs; command/UI/controller identities retain z. Freight material sources retain their actual deck while shuttle-owned parcels remain at the real terminal.

The browser floor selector now passes explicit z through map picking, tile lookup, job placement and the supported equipment controls. Rendering filters floors, actors, jobs, sources, impacts and overlays by the view. Floor changes expire pressed-control scopes; crew/maintenance/hazard navigation uses actual positions. Ground-only battery-cell loading remains hidden upstairs until its action supports z.

Schema56 stair-maintenance jobs own a connection ID and claim both landings. Repair targets either end; removal normalizes work to the lower end and preserves both floor tiles. Save admission validates the connection, price, work, endpoint conflicts and actual source decks. Generic tile reservations now include z, so independent same-x/y jobs on different floors can reload.

## Cultivation checkpoint (schema62)

Planting, watering and gathering now resolve full positions through validation, completion, reservations and event identities. Paid planter beds make these jobs usable on constructed floors. Plant panels use actual-floor crew routes, supplies and designation ownership; ground and stacked panel keys remain distinct. Finite irrigation and moisture returns retain the bed location. Terrain extraction and terminal-specific upper work remain pending.

## Extraction checkpoint (schema63)

Ice/impact reserves, natural terrain and salvage use shared source rules on the requested floor. Work, cancellation, completion, deposits, loose piles and event identities use full positions. Debris damage and retained material share the impact location. Native stair hauling carries recovered ore to storage. Construction blocks on active reserves at ordering and execution. Current fixed shuttle/expedition terminals remain on their existing floors.

## Personal item and prepared-meal custody checkpoint

Personal item release and death now resolve the actual crew tile. Pickup planning, ownership/release and meal-preparation events retain z. Shared inventory-owner enumeration uses canonical full-floor tile IDs, so both discrete items and split meal batches report their actual owners. Ground IDs remain stable; saves and observation schema are unchanged. Native stair pickup, closed-hatch cancellation/recovery, release, death and subsequent hauling pass bounded checks.
